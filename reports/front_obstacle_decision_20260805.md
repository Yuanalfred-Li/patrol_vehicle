# 前向障碍安全接入方案决策（2026-08-05）

## 1. 背景与目标

交接文档阶段 H（安全层）要求打通前向障碍闭环（分级减速 → 紧急停车）。现有两个可用组件：

- **A：`lidar_distance_interface` + 健康节点**（ros2_humble_main）——只读"前方净空距离"测量接口，契约/实测证据齐全（文档：FRONT_CLEARANCE_SUBSCRIPTION_GUIDE.md）
- **B：`scan_gap_follower`**（ros2_humble_main）——完整 360° 避障控制器，能直接发布 `VehicleCommand`

## 2. 现状事实（红线）

- `/vehicle/command` 发布者必须唯一且为 `patrol_command_manager`（交接 §6.3）；STOP/MANUAL/AUTO 仲裁、任务状态机、命令超时停车均在该节点
- patrol_ws 目前无任何雷达障碍输入（§20.5：障碍物安全未完成）
- B 无任务/模式感知：不认 STOP/MANUAL/AUTO，不认任务状态机；A 只读，天然无冲突

## 3. 方案对比

| 维度 | A：净空接口 + patrol 守护节点 | B：scan_gap_follower 直接接底盘 |
|---|---|---|
| 障碍感知 | 前向 0±20°、0.25~3.0m（纵向净空） | 360°、1/2/3m 分层、找间隙绕行 |
| 决策输出 | 新守护节点做分级减速/停车 | CRUISE/SLOW_DOWN/AVOID/STOP/BLOCKED |
| 架构影响 | 新增 1 节点 + 挂入现有仲裁，**单发布者红线不破** | 需外部门控（任务运行时才接管），否则**破坏仲裁** |
| 底盘参数 | 无（只输出距离） | 需确认 wheel_radius/reduction 的 RPM 换算、车宽 0.50→0.80m |
| 标定依赖 | 无 | `0x701` 反馈尚不可信（§20.7），rpm 换算未实车验证 |
| 现场证据 | 测距实测（1.21m 桶 / 2.78m 靶标 / 断流超时） | 状态机有合成预检 + 实车基础测试 |
| 工作量 | 1 节点 + 仲裁挂接 + 仿真/实车 | 门控封装 + 参数标定 + 仲裁挂接（更大） |

## 4. 关键判断

1. **两条路最终都要过同一道仲裁**——B 不能直接独占 `/vehicle/command`（否则手动模式/急停失效），所以"接 B"实际是"B + 门控"，工作量不小
2. B 的 rpm 换算与车宽参数**依赖未标定的底盘数据**（§20.3/§20.7），直接闭环有安全风险
3. A 与阶段 H 的验收路径一致（前向障碍→分级减速→紧急停车），改动最小、可先离线仿真验证
4. A 的 ±20° 扇区不含侧方——**后续**若要绕行/侧方安全，再在守护节点层扩展或引入 B 的 360° 感知

## 5. 推荐：方案 A 先行（纵向安全闭环），B 作为后续 360° 演进

理由：不破单发布者红线；不依赖未标定底盘参数；与阶段 H 验收路径一致；可独立仿真验证。

### 若采纳 A 的落地步骤（阶段 H 子集）
1. patrol_ws 新增 `patrol_obstacle_guard` 节点：订阅净空距离 + 健康话题，实现三态（SCAN_STALE/CLEAR_WITHIN_3M/OBSTACLE_AT_RANGE）
2. 分级逻辑：远（2~3m）限速 → 近（≤1m）停车，`SCAN_STALE` 一律按失效停车处理（与 GNSS 弱化保持同风格，独立于任务状态机）
3. 挂接仲裁：守护节点输出进入 `patrol_command_manager` 的 STOP 优先级（AUTO 时生效，MANUAL 只告警不抢控）
4. 参数/launch 接入 patrol_system.launch.py；仿真模拟 `/scan` 后全回归
5. 实车前确认上游 `pointcloud_to_laserscan` 的自车过滤已按本车完成（文档 §2 前置条件）

### 若采纳 B 的前置条件（暂不满足）
- 完成转向与 RPM 实车标定（§20.3/§20.7）→ 确认 `speed_to_rpm` 映射
- 设计门控：仅任务 AUTO 且未手动接管时允许 B 输出进入 `/vehicle/command`
- 车宽/安全边距按 0.80m 实测配置
